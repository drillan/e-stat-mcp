# Feature Specification: e-Stat API連携MCPサーバー

**Feature Branch**: `001-e-stat-mcp`
**Created**: 2026-01-07
**Status**: Draft
**Input**: User description: "e-Stat API連携MCPサーバーの作成"

## Overview

政府統計の総合窓口（e-Stat）が提供する統計データをMCP（Model Context Protocol）を通じてAIアシスタントから利用可能にするMCPサーバーを作成する。これにより、ユーザーはAIアシスタントとの対話を通じて、日本の政府統計データを簡単に検索・取得・分析できるようになる。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 統計データの検索 (Priority: P1)

ユーザーとして、AIアシスタントに「人口に関する統計を探して」と依頼することで、e-Statで公開されている関連統計表の一覧を取得したい。

**Why this priority**: 統計データを利用する最初のステップは、必要なデータを見つけることであり、これがなければ他の機能は意味をなさない。

**Independent Test**: キーワードを指定して統計表を検索し、該当する統計表の一覧（統計表ID、名称、調査年等）が返却されることを確認する。

**Acceptance Scenarios**:

1. **Given** MCPサーバーが起動している状態, **When** 「人口」というキーワードで統計表を検索する, **Then** 人口に関連する統計表の一覧（統計表ID、名称、調査年を含む）が返却される
2. **Given** MCPサーバーが起動している状態, **When** 存在しないキーワードで検索する, **Then** 該当なしの旨が適切なメッセージで返却される
3. **Given** MCPサーバーが起動している状態, **When** 政府統計コードを指定して検索する, **Then** 該当する政府統計に属する統計表の一覧が返却される

---

### User Story 2 - 統計データの取得 (Priority: P1)

ユーザーとして、統計表IDを指定して実際の統計データ（数値データ）を取得したい。

**Why this priority**: 検索に並ぶ最重要機能であり、統計データの実際の活用に必須である。

**Independent Test**: 統計表IDを指定してデータを取得し、表章事項・分類事項・数値データが構造化された形式で返却されることを確認する。

**Acceptance Scenarios**:

1. **Given** 有効な統計表IDがわかっている状態, **When** その統計表IDを指定してデータを取得する, **Then** 統計データ（数値、項目名、単位等を含む）が返却される
2. **Given** 有効な統計表IDがわかっている状態, **When** 地域や時点で絞り込み条件を指定してデータを取得する, **Then** 絞り込まれた統計データが返却される
3. **Given** 存在しない統計表IDを指定した場合, **When** データを取得しようとする, **Then** 該当なしの旨が適切なエラーメッセージで返却される

---

### User Story 3 - 統計表のメタ情報取得 (Priority: P2)

ユーザーとして、統計表の詳細情報（どのような項目・分類があるか等）を事前に確認したい。

**Why this priority**: データ取得の前に構造を理解することで、効率的な絞り込み条件の指定が可能になる。

**Independent Test**: 統計表IDを指定してメタ情報を取得し、表章事項・分類事項・地域事項等の情報が返却されることを確認する。

**Acceptance Scenarios**:

1. **Given** 有効な統計表IDがわかっている状態, **When** その統計表IDのメタ情報を取得する, **Then** 表章事項、分類事項、地域事項、時点情報等が返却される
2. **Given** メタ情報を取得した状態, **When** 返却された分類コードを使ってデータを絞り込み取得する, **Then** 正しく絞り込まれたデータが取得できる

---

### User Story 4 - 公開データセットの参照 (Priority: P2)

ユーザーとして、他のユーザーが公開しているデータセット（事前定義された絞り込み条件）を参照し、それを使って効率的に統計データを取得したい。

**Why this priority**: データセットを活用することで、複雑な絞り込み条件を自分で指定せずに、よく使われる形式でデータを取得できる。

**Independent Test**: 公開データセットの一覧を取得し、データセットIDを使って統計データを取得できることを確認する。

**Acceptance Scenarios**:

1. **Given** MCPサーバーが起動している状態, **When** 公開データセットの一覧を取得する, **Then** 利用可能なデータセット（ID、名称、対象統計表等）が返却される
2. **Given** 有効なデータセットIDがわかっている状態, **When** そのデータセットIDを指定してデータを取得する, **Then** データセットに定義された絞り込み条件で統計データが返却される

---

### User Story 5 - APIキーの設定 (Priority: P1)

ユーザーとして、自分のe-StatアプリケーションIDをMCPサーバーに設定して、APIを利用したい。

**Why this priority**: e-Stat APIの利用にはアプリケーションIDが必須であり、これがなければ他のすべての機能が動作しない。

**Independent Test**: アプリケーションIDを設定し、APIリクエストが正常に認証されることを確認する。

**Acceptance Scenarios**:

1. **Given** 有効なアプリケーションIDを持っている状態, **When** MCPサーバーの設定でアプリケーションIDを設定する, **Then** 設定が正常に保存され、API呼び出しが成功する
2. **Given** 無効なアプリケーションIDを設定した状態, **When** APIを呼び出す, **Then** 認証エラーの旨が適切なメッセージで返却される
3. **Given** アプリケーションIDが設定されていない状態, **When** APIを呼び出そうとする, **Then** 設定が必要である旨のエラーメッセージが返却される

---

### Edge Cases

| ケース | 挙動 | エラーメッセージ |
|--------|------|------------------|
| 大量データ取得（10万件超） | limit/start_positionによるページネーションを案内 | 「データ件数が上限を超えています。start_positionを指定して分割取得してください。」 |
| e-Stat APIメンテナンス | HTTPステータスで判定し、リトライ不可として即座にエラー返却 | 「e-Stat APIが現在メンテナンス中です。しばらく待ってから再度お試しください。」 |
| APIレート制限 | 指数バックオフで最大3回リトライ後、エラー返却 | 「APIリクエスト制限に達しました。しばらく待ってから再度お試しください。」 |
| 無効な絞り込み条件 | Pydanticバリデーションエラーを返却 | 「指定された条件が不正です: {詳細}」 |
| ネットワークタイムアウト | 指数バックオフで最大3回リトライ後、エラー返却 | 「接続がタイムアウトしました。ネットワーク状況を確認してください。」 |

## Requirements *(mandatory)*

### Functional Requirements

#### コアAPI機能（e-Stat API連携）

- **FR-001**: システムはe-Stat APIの統計表情報取得機能（getStatsList）をMCPツールとして提供しなければならない
- **FR-002**: システムはe-Stat APIの統計データ取得機能（getStatsData）をMCPツールとして提供しなければならない
- **FR-003**: システムはe-Stat APIのメタ情報取得機能（getMetaInfo）をMCPツールとして提供しなければならない
- **FR-004**: システムはe-Stat APIのデータセット参照機能（refDataset）をMCPツールとして提供しなければならない

#### 検索・フィルタリング機能

- **FR-005**: システムはキーワード、政府統計コード、調査年等による統計表の検索機能を提供しなければならない
- **FR-006**: システムは統計データの絞り込み条件（地域、時点、分類等）の指定をサポートしなければならない
- **FR-007**: システムは大量データの分割取得（ページネーション）をサポートしなければならない

#### 設定・エラー処理

- **FR-008**: システムはe-StatアプリケーションIDの設定機能を提供しなければならない
- **FR-009**: システムはAPIエラー（認証エラー、データなし、レート制限等）を適切なメッセージで返却しなければならない

#### データ形式・品質

- **FR-010**: システムはJSON形式をデフォルトとしてデータを返却しなければならない
- **FR-011**: システムは取得したデータをAIアシスタントが解釈しやすい構造化された形式で返却しなければならない
- **FR-012**: システムはAPIレスポンスをキャッシュし、同一リクエストの再実行時にキャッシュからデータを返却しなければならない。デフォルトTTLは3600秒（1時間）とし、環境変数`E_STAT_CACHE_TTL_SECONDS`で設定可能とする
- **FR-013**: システムはAPIリクエスト失敗時に最大3回まで指数バックオフで自動リトライしなければならない

### Key Entities

- **統計表（StatsTable）**: 政府統計に含まれる個別の統計表。統計表ID、名称、政府統計コード、調査年、公開日等の属性を持つ
- **統計データ（StatsData）**: 統計表に含まれる実際の数値データ。表章事項、分類事項、地域、時点、数値、単位等の属性を持つ
- **メタ情報（MetaInfo）**: 統計表の構造情報。表章事項リスト、分類事項リスト、地域リスト、時点リスト等を含む
- **データセット（DataSet）**: 統計表に対する事前定義された絞り込み条件のセット。データセットID、名称、対象統計表ID、公開状態等の属性を持つ
- **アプリケーションID（AppId）**: e-Stat APIを利用するための認証情報

## Assumptions

- ユーザーは事前にe-Statでユーザー登録を行い、アプリケーションIDを取得済みである
- MCPサーバーはローカルまたはアクセス可能な環境で実行される
- e-Stat API 3.0を使用し、公式ドキュメントに記載された仕様通りに動作する
- AIアシスタント（Claude等）はMCPプロトコルをサポートしている
- e-Stat APIへのリクエストは日本語（lang=J）のみを使用する

## Clarifications

### Session 2026-01-07

- Q: デフォルトレスポンス形式は何か？ → A: JSON形式をデフォルトとし、ユーザーが明示的に指定した場合のみ他の形式を使用
- Q: 使用するe-Stat APIバージョンは？ → A: API 3.0のみをサポート（最新の安定版）
- Q: キャッシュ戦略は？ → A: 短期キャッシュ（検索結果を数分〜数時間保持）
- Q: 言語サポートは？ → A: 日本語のみをサポート
- Q: APIタイムアウトとリトライ戦略は？ → A: 最大3回まで自動リトライ（指数バックオフ）
- Q: データセット登録API (FR-003a) の扱いは？ → A: 削除（不要）- ユーザーがe-Stat上で直接管理すべき機能
- Q: データカタログ情報取得・統計データ一括取得の扱いは？ → A: 両方削除 - PoCではコア4APIに集中
- Q: データセット参照のUser Story追加は？ → A: 追加する - 公開データセット活用のシナリオを追加

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーはキーワードを指定して統計表を検索し、5秒以内に結果を取得できる
- **SC-002**: ユーザーは統計表IDを指定して統計データを取得し、標準的なデータ量であれば10秒以内に結果を取得できる
- **SC-003**: ユーザーはMCPクライアント（AIアシスタント）から自然言語で統計データへのアクセスを依頼できる
- **SC-004**: 初回セットアップ（アプリケーションIDの設定）は5分以内に完了できる
- **SC-005**: e-Stat APIのすべてのエラーレスポンスに対して、ユーザーが次のアクションを理解できる説明的なメッセージが返却される
